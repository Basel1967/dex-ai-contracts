# Event Envelope v1.0.0 — Semantic Closure Candidate

Status: **Draft / publication blocked by evidence-backed open P0 items**. This closes the previously unresolved technical semantics without erasing SESSION 17 history.

## Normative profile

The JSON Schema is authoritative for field shapes, requiredness, nullability, closed enums, nested properties and conditional presence. Missing differs from `null`; empty strings and zero-as-unknown are forbidden. Only fields explicitly unioned with `null` have null semantics. `related_entity_refs` may be empty; payload may not.

Identifiers are case-sensitive opaque URNs. Event IDs are `urn:dex-ai:event:<32 lowercase hex>` and never reused. Entity refs identify token, pool, wallet, social or token-case and explicitly say `canonical` or `provisional`. Idempotency and payload hashes are lowercase SHA-256. IDs never contain secrets, credentials or PII.

Timestamps use UTC RFC 3339 with literal `Z` and exactly six fractional digits. Leap seconds are rejected. `observed_at <= ingested_at <= available_at` when available. Source event time may lead observation by at most two seconds and is flagged `CLOCK_SKEW_TOLERATED`; larger skew quarantines. On-chain order is slot, transaction signature, instruction index, inner index. Off-chain order is source sequence plus record ID. Arrival order is never event truth. If total order cannot be proven, retain and flag the event; do not invent an order.

## Integrity and raw evidence

`payload_hash` and `integrity.digest` are SHA-256 over UTF-8 canonical JSON payload using the repository's RFC8785-JCS profile: sorted keys and no insignificant whitespace. Missing hash, unsupported algorithm or mismatch prevents availability and causes quarantine. Raw evidence is immutable and uses an artifact identity plus allowlisted locator. HTTP URLs, traversal, query credentials and signed URLs are forbidden.

## Trace context

The profile adopts W3C lowercase trace-id (32 hex), span-id (16 hex), flags (2 hex), optional tracestate and nullable parent span for roots. Baggage is forbidden. Trace context is operational; `correlation_id` is business linkage; `causation_event_id` is event lineage.

## Replay

Replay pins run, cutoff, dataset, snapshot, artifacts, schemas, policies, code, environment and seed. Eligibility requires non-null `available_at <= cutoff_at`. Replay never changes an original event; outputs are new append-only events with replay provenance.

## Duplicate, late and out-of-order

- Duplicate event ID or transport redelivery: preserve original evidence, suppress reprocessing and audit delivery.
- Duplicate idempotency key with new event ID: retain/link it and suppress repeated business effect. Corrections, supersessions and revocations are not duplicates.
- Late: older than the domain watermark (default live profile five minutes). Store, flag and trigger case reevaluation; never rewrite historical snapshots.
- Out-of-order: position precedes the highest accepted position for its ordering key. Store, flag and reprocess deterministically. Missing anchor is not automatically bad.

## Compatibility

This is draft completion, not compatibility with a published predecessor: `NOT_APPLICABLE_UNPUBLISHED_PREDECESSOR`. Future required fields, enum additions, pattern or nested-shape changes require compatibility analysis. Published artifacts are immutable.
